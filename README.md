# prompt-builder — 대충 쓴 요청을 실행용 프롬프트로 바꾸는 스킬

평소처럼 대충 요청을 쓰면 스킬이 저장소를 확인해 **실행용 프롬프트**를 만들어 보여 줍니다. 승인하면 그 프롬프트를 기준으로 작업합니다.

```
사용자:  @skills:prompt-builder docs/setup.md에 윈도우 설치 방법 추가해 줘

Devin:   목표: docs/setup.md에 Windows 설치 방법 절을 추가한다
         대상: docs/setup.md
         완료 기준:
           - docs/setup.md에 `## Windows 설치` 절이 생긴다 (기존 `## macOS 설치`와 같은 제목 수준)
         검증: (확인 필요) — 저장소에 문서 검사 명령이 없음
         제약: AGENTS.md — 문서는 한국어로 작성
         가정:
           - 기존 절의 내용은 고치지 않는다고 봄 (변경 범위가 가장 작은 해석)
           - 설치 방식(설치 파일 / 패키지 관리자)은 요청에 없음 (확인 필요)

         이 프롬프트로 진행할까요? (진행 / 고칠 부분 알려 주기 / 프롬프트만 받기)
```

요청이 너무 비어 있으면(예: "로그인 버그 고쳐 줘") 프롬프트를 지어내지 않고, 무엇이 문제인지 1~2개만 먼저 묻습니다.

## 왜 필요한가

상위 모델은 짧은 요청의 빈칸을 스스로 잘 메웁니다. Opus 4.6처럼 제한된 모델은 빈칸을 **추측으로** 메웁니다. 이 스킬은 작업 전에 빈칸을 채우는 단계를 강제합니다.

- **확인된 것:** 대상 경로가 저장소에 있는지는 파일 시스템으로 확인합니다.
- **후보:** 검증 명령은 설정 파일 기준 후보입니다.
- **사용자 확인:** 확인할 수 없는 것은 `가정:`으로 따로 표시해서 사용자에게 묻습니다.

## 설치

```bash
# 저장소에 넣기 (팀 공유, 커밋 대상)
mkdir -p .agents/skills
cp -r skills/prompt-builder .agents/skills/

# 또는 내 PC 전체에서 쓰기 (Devin CLI)
mkdir -p ~/.config/devin/skills
cp -r skills/prompt-builder ~/.config/devin/skills/
```

- 저장소에 넣으면 Devin 웹 앱과 클라우드 세션에서도 씁니다. Devin은 클론한 저장소의 `.agents/skills/`를 읽습니다.
- 보조 스크립트 위치는 스킬이 직접 찾습니다. 찾는 순서는 `.agents/skills`, `.devin/skills`, `.claude/skills`, `.github/skills`, `~/.config/devin/skills`, `~/.agents/skills`입니다. 전역 설치해도 `SKILL.md`를 고칠 필요가 없습니다. 못 찾으면 "…없음 — 건너뜀"을 출력하고 스킬이 직접 점검합니다.
- Devin 웹의 Customize → Skills에 `SKILL.md`만 붙여 넣어 등록할 수도 있습니다. 이때는 보조 스크립트가 없으므로, 스킬이 1단계를 건너뛰고 모호한 표현·위험 작업·작업 크기를 직접 점검합니다.

## 쓰는 법

| 환경 | 호출 |
|---|---|
| Devin 웹·Slack | `@skills:prompt-builder 대충 쓴 요청` |
| Devin CLI | `/prompt-builder 대충 쓴 요청` |

- **자동 호출:** 처음에는 꺼 두었습니다(`triggers: ["user"]`). "프롬프트 만들어 줘"가 이미지 생성 프롬프트 같은 다른 요청에도 걸릴 수 있어서입니다. 써 보고 괜찮으면 `SKILL.md` 앞머리에서 그 줄을 지우세요.
- **바로 진행:** 요청에 "바로 실행"을 넣고 대상과 완료 기준까지 적으면 확인 없이 진행합니다. 가정이나 위험 작업이 있으면 그때도 묻습니다.
- **작업이 큰 경우:** "프롬프트 1/3, 2/3…"으로 나눠 줍니다. 이 세션에서는 1번만 진행하고, 나머지는 새 세션에 쓰세요.
- **위험 작업:** push, 커밋, PR, 머지, 배포, 운영 반영, 삭제, DB 변경 등은 "진행" 한마디로는 실행하지 않습니다. 작업 이름을 들어 승인해야 합니다. 단어가 대상 이름일 뿐인 요청("삭제 버튼 만들어 줘", "PR 템플릿 고쳐 줘")은 위험 작업으로 보지 않습니다.
- **커밋·PR은 따로 말해야 합니다:** "진행"하면 파일 수정까지만 하고 커밋·PR 없이 끝납니다. PR까지 원하면 "진행, PR도 올려 줘"처럼 작업 이름을 들어 승인하세요.

## 구성

```
skills/prompt-builder/
├── SKILL.md            스킬 본문: 규칙, 절차 5단계, 프롬프트 형식, 내보내기 전 점검(lint), 예시 2개
├── prompt_helper.py    요청·저장소 단서 뽑기 (1단계)
└── prompt_lint.py      만든 프롬프트 점검 (3단계 끝) — prompt_helper.py를 함께 씀
tests/
├── test_prompt_helper.py
└── test_prompt_lint.py
```

두 스크립트 모두 표준 라이브러리만 쓰고 Python 3.8 이상에서 돕니다.

### lint — 만든 프롬프트 점검

요청 분석은 키워드 추측이라 틀릴 수 있지만, 만든 프롬프트는 `목표:`, `대상:`처럼 칸이 정해져 있어서 **칸 단위로 정확하게** 점검할 수 있습니다. 스킬은 프롬프트를 보여 주기 전에 lint를 돌리고, ✗가 있으면 그 칸만 고쳐 다시 돌립니다. **점검은 모두 3번까지만** 합니다. 3번째에도 ✗가 남으면 더 돌리지 않고, 남은 ✗를 사용자에게 그대로 보여 줍니다. Opus 4.6이 체크리스트를 보고 스스로 판단하던 부분을 스크립트 판정으로 바꾼 것입니다.

**설계 원칙: ✗는 고칠 방법이 분명한 것만 냅니다.** 4.6은 ✗를 없애려고 멀쩡한 내용을 바꾸거나 `(확인 필요)`를 남발할 수 있습니다. 그래서 애매한 것(후보에 없는 검증 명령, "제대로" 같은 약한 표현)은 △로만 알립니다.

| 판정 | 점검 내용 |
|---|---|
| ✗ 오류 | 필수 칸(목표·대상·완료 기준·검증·제약·가정)이 없음, 비었음, 템플릿 자리표시자가 남음 |
| ✗ 오류 | 대상에 경로가 없음, 저장소 밖 경로, 또는 저장소에 없는 경로 뒤에 `(새 파일)`·`(확인 필요)` 표시가 없음. 표시는 항목마다 따로 봄. 한글 경로(`문서/가이드/설치.md`)와 `Dockerfile` 같은 확장자 없는 파일도 인식. `LoginService.login()` 같은 코드 식별자는 경로로 보지 않음 |
| ✗ 오류 | 완료 기준에 확인할 수 없는 표현("잘 동작", "정상적으로", "문제없이", "이상 없이", "올바르게 동작"). 따옴표·백틱으로 인용한 화면 문구는 제외 |
| △ 경고 | 검증 명령이 저장소 후보에 없음. 후보에는 package.json의 모든 scripts가 포함되고, `npm test`=`npm run test`, `--filter`·`-C` 같은 위치 옵션을 인정함. 후보 뒤에 인자를 붙이면 △. `(출처: .github/workflows/ci.yml)`을 붙이면 **그 파일에 명령이 실제로 있을 때만** 경고가 사라짐(지어낸 출처 방지). 출처는 그 명령에만 적용 |
| △ 경고 | 완료 기준의 약한 표현("제대로", "완벽", "적절", "안정적", "향상" 등), 모호한 표현, 제약에 출처 없음, 위험 작업 표현(키워드 기준), 목표 200자 초과, 칸 이름 변형(`완료기준:` 등 — 인식은 함) |

```bash
python3 skills/prompt-builder/prompt_lint.py <<'PROMPT_BUILDER_EOF'
목표: ...
대상: ...
PROMPT_BUILDER_EOF
```

종료 코드는 오류가 없으면 0, 있으면 1, 입력 오류면 2입니다. "프롬프트 1/3"처럼 나눈 프롬프트는 `목표:`마다 나눠 각각 점검합니다.

`prompt_helper.py`가 하는 일과 정확도:

| 확인 | 방법 | 정확도 |
|---|---|---|
| 빠진 항목 | 대상·완료 기준·검증·제약 표현이 요청에 있는지 | **참고용.** 키워드 기반이라 틀릴 수 있음 |
| 모호한 표현 | "알아서", "적당히", "깔끔하게", "지난번처럼" 등 | 참고용 |
| 위험 작업 | push·force·`reset --hard`·커밋·PR·머지·배포·릴리스·production/운영 반영·삭제·drop·마이그레이션 | 참고용. 단어만 보므로 놓치기도 하고("지워 줘"), 오탐도 있음("삭제 버튼"). 스킬이 실제 실행 요청인지 직접 판단함 |
| 작업 크기 | 목록 6개 이상 또는 4000자 초과 | 참고용 |
| 경로 | 요청에 나온 경로가 저장소 안에 있는지. 파일 이름만 있으면 저장소에서 찾음(대소문자 무시로 한 번 더, `node_modules`·`build` 등 제외, `.github`는 포함). URL·이메일·공백 든 백틱·저장소 밖 경로는 제외 | **확정.** 파일 시스템 기준 |
| 검증 명령 | 루트와, 대상 경로에서 가장 가까운 하위 프로젝트의 설정 파일. `package.json` scripts(npm/pnpm/yarn/bun, npm 기본 test 문구 제외), `gradlew`, `pom.xml`, `pubspec.yaml`(flutter/dart), pytest(uv), Cargo, Go, Makefile | **후보.** 설정 파일이 있다는 것만 보고 판단하므로 실행 전 확인 필요 |

한국어 조사가 붙은 경우(`Login.kt에서`, `push해줘`)도 잡습니다. 저장소 루트는 `--root`, git 최상위, 현재 폴더 순서로 정합니다. 결과 첫 줄에 루트가 나오고, git 저장소가 아니면 경고를 붙입니다.

```bash
python3 skills/prompt-builder/prompt_helper.py scan --text <<'PROMPT_BUILDER_EOF'
로그인 버그 고쳐 줘 알아서
PROMPT_BUILDER_EOF
```

키워드와 기준값은 파일 맨 위 "조정 가능한 설정"에 모여 있습니다. 회사에서 이상한 판정이 나오면 그 요청을 `tests/`에 추가한 뒤 키워드를 고치세요.

## 테스트

```bash
python3 -m unittest discover -s tests
```

테스트는 90개이고, Python 3.9와 3.15에서 통과를 확인했습니다. SKILL.md의 셸 명령은 bash와 zsh 모두에서 실제로 돌려 봅니다. 다루는 범위는 다음과 같습니다.

- 한국어 활용형과 조사
- 알려진 오탐
- 경로 잡음(URL, 이메일, 버전 번호)
- 깨진 설정 파일(BOM, EUC-KR, 잘못된 JSON)
- 모노레포
- CLI 입력 오류
- lint: 칸 누락·자리표시자·칸 이름 변형·없는 경로·새 파일·항목별 표시·코드 식별자·검증 명령 변형 14가지·관찰할 수 없는 완료 기준과 인용 문구·나눈 프롬프트
- `SKILL.md`와 스크립트의 계약: 출력 줄 이름, 위험 작업 목록, 템플릿, heredoc 구분자, **SKILL.md 예시가 lint를 통과하는지**, 셸 명령이 실제로 도는지

## 회사에서 처음 한 번 확인할 것

이 PC에는 Devin이 없어서 아래 세 가지는 확인하지 못했습니다.

1. **`$ARGUMENTS` 치환:** 웹(`@skills:`)과 CLI(`/prompt-builder`)에서 각각 한 번씩 호출해 요청이 제대로 들어가는지 봅니다. Devin 문서에서는 웹 기준으로만 설명돼 있습니다. 치환이 안 되면 사용자 메시지에서 요청을 가져오도록 대비 문구를 넣어 두었습니다.
2. **작업 디렉터리:** 1단계 명령이 저장소 루트를 제대로 찾는지 봅니다. 결과 첫 줄의 "저장소 루트"를 확인하면 됩니다.
3. **멈춤:** 4단계에서 실제로 멈추고 응답을 기다리는지 봅니다. 또 "진행"만 했을 때 커밋이나 push를 하지 않는지도 봅니다. Devin은 작업 후 PR을 만드는 것이 기본 동작일 수 있습니다.

## OMD에 넣을 때

최신 OMD 코드는 보지 못했습니다. 예전 0.3.0 기준으로 필요한 작업은 두 가지입니다.

1. `skills/prompt-builder` 폴더와 `tests/test_prompt_helper.py`, `tests/test_prompt_lint.py`를 OMD로 옮기고, 스킬 등록부에 추가합니다.
2. 0.3.0의 설치 코드는 `SKILL.md` 내용만 복사합니다. 설치할 때 **폴더 전체를 복사**하도록 바꿔야 보조 스크립트가 따라갑니다. 바꾸지 않아도 스킬은 동작하지만, 1단계를 건너뛰고 에이전트가 직접 점검합니다.

## 권한 확인 창에 대해

`allowed-tools`에 `exec`를 일부러 넣지 않았습니다. Devin에서 `allowed-tools`는 제한이 아니라 자동 승인 목록이라, `exec`를 넣으면 스킬이 도는 동안 `git push` 같은 명령도 확인 없이 실행될 수 있기 때문입니다. 그래서 CLI에서는 보조 스크립트를 돌릴 때마다 권한 확인 창이 뜰 수 있습니다. 거슬리면 회사 정책에 맞게 `exec`를 추가하되, 그 대신 Devin의 `permissions`로 push·배포 명령을 막는 것을 권합니다.
